# AGENTS.md

## What this is

Vue 3 + Vite single-page app that renders a personal CV/resume. The final output is **printed to A4 PDF** via `vue-to-print`. The app supports **multiple resume templates** selectable at runtime via `<USelect>`.

The architecture is intentionally minimal — a templates registry in `src/App.vue` is the single source of truth. Adding a new template = drop a `.vue` file in `src/components/resume/` and add one entry to the `templates` array.

`.data/*.md` is throwaway draft content (not the live source of truth) and is gitignored. Don't treat it as canonical resume data.

## Stack & toolchain quirks

- **Bun only** — package manager is Bun (`bun.lock`). No `package-lock.json`/`pnpm-lock.yaml`. Use `bun install`, `bun dev`, etc.
- **Vue is on the `rc` channel** — `vue: rc` in `package.json` plus a full `@vue/*` `overrides` block pinning every Vue sub-package to `rc`. Do not bump Vue or its sub-packages to a stable version without explicit intent.
- **oxlint + oxfmt, not ESLint + Prettier.** `oxlint.config.ts` and `oxfmt.config.ts` are the source of truth. The README still mentions ESLint — ignore it. oxfmt: 2-space, double quotes, semicolons, `trailingComma: "all"`, `printWidth: 100`.
- **oxlint disables `@typescript-eslint/no-explicit-any`** — `as any` is allowed (and used, e.g. `useVueToPrint({ content: sheetRef as any })`).
- **Typecheck uses `vue-tsc --build`** (project references across `tsconfig.app.json` + `tsconfig.node.json`). `tsBuildInfoFile` is redirected to `node_modules/.tmp/`.
- **`tsconfig.app.json` has `noUncheckedIndexedAccess: true`** — array/object index access returns `T | undefined`. Code accordingly (don't assume `array[i]` is defined).
- **`@nuxt/ui` plugin** is registered in `src/main.ts` with `router: false, colorMode: false` (see `vite.config.ts`). Neutral color is `zinc`.
- **`@nuxt/ui` vite plugin** has `prose: true` (auto-registers prose components) and `autoImport.imports: ["vue", "@vueuse/core"]` (so Vue core + VueUse APIs are auto-imported — `ref`, `computed`, `resolveComponent`, `createReusableTemplate` need no import statement).

## Commands

```sh
bun install         # install deps
bun dev             # vite dev server
bun run build       # typecheck + build in PARALLEL via run-p (NOT sequential)
bun run preview     # serve dist/
bun run typecheck   # vue-tsc --build
bun lint            # oxlint
bun lint:fix        # oxlint --fix
bun fmt             # oxfmt (write)
bun fmt:check       # oxfmt --check
```

`bun run build` runs `typecheck` and `build-only` concurrently. Both must pass; they do not depend on each other.

## Auto-import behavior

- **Vue + VueUse APIs** are globally auto-imported (`ref`, `computed`, `resolveComponent`, `createReusableTemplate`, etc.). Don't add explicit imports for them.
- **Nuxt UI components** are auto-imported as `U*` (`UButton`, `UApp`, `USelect`, `USeparator`, `UTimeline`, `UIcon`).
- **Local SFCs under `src/components/` ARE auto-imported** via `unplugin-vue-components` — they become available globally. To use a local SFC as a component reference (not just in template), use `resolveComponent("Name")` rather than an explicit `import` — see how `App.vue` resolves `"Modern"`.
- `@comark/vue`'s `<Comark>` is NOT auto-imported — explicit `import { Comark } from "@comark/vue"` is required.

## Print behavior

- `src/assets/main.css` sets `@page { size: A4; margin: 12mm 0 }` so every page has symmetric vertical padding from the page edge.
- The same `@page` block sets `content: none` on all six header/footer margin boxes (`@top-left`/`@top-center`/`@top-right` and `@bottom-*`) to suppress the browser's default date / URL / page-number / title overlays. Supported in modern Chrome (131+) via CSS Paged Media Level 3; older browsers ignore the rule.
- Resume article (`src/App.vue`) has `print:py-0` so it doesn't stack internal vertical padding on top of the `@page` margin.
- `vue-to-print` is invoked with `content: sheetRef as any` — `sheetRef` points at the outer wrapper containing the active template, so switching templates doesn't break print.

## Multi-template architecture

Single source of truth: the `templates` array in `src/App.vue`. Adding a template:

1. Create `src/components/resume/<Name>.vue`. Wrap its top-level `<article>` in `<Suspense>` if it (or any descendant) uses async components.
2. Add one entry to the `templates` array — `{ id, name, component: resolveComponent("<Name>") }`. The `as const` literal type means `TemplateId` auto-extends.
3. The Select items and `<component :is="activeTemplate.component" />` rendering update automatically.

The section header pattern (heading + `<USeparator>` + content) is shared via `createReusableTemplate` in `Modern.vue` — use the same `<DefineResumeSection>` / `<ReuseResumeSection>` pair when building new templates that follow the same shape.

## Comark quirks

- `<Comark>` from `@comark/vue` has `async setup()` — Vue requires every async component to have a `<Suspense>` ancestor. Wrap the entire template (or each `<Comark>`) in `<Suspense>`, otherwise Vue logs the warning `<Comark> is an async component and must always be wrapped in <Suspense>`.
- Comark wraps rendered markdown in `<div class="comark-content">`. To control inner spacing, use Tailwind arbitrary-variant classes on `<Comark>` itself — e.g. `class="[&>*:first-child]:mt-0 [&>*:last-child]:mb-0"` — scoped CSS with `:deep()` does not reach Comark's children.
- Each bullet section is a single markdown string (not `string[]`); render via `<Comark :markdown="...">` directly. The earlier `toMarkdownList` helper was removed.

## Conventions specific to this repo

- Resume content goes into Vue components (or wherever you wire it up). `.data/*.md` is just scratch/draft material.
- New fonts require both the `@font-face` block in `index.html` (for FOIT) **and** the matching block in `src/assets/main.css`.
- `@nuxt/ui` semantic color classes (`text-default`, `bg-elevated`, `border-inverted`, etc.) — never use raw Tailwind palette colors in components. `border-highlight` does not exist; use `border-inverted` for the strongest divider line.
- Use `<USeparator :ui="{ border: 'border-inverted' }" />` for section dividers — not CSS `border-b`.
- The `.agents/skills/nuxt-ui` skill is the canonical reference for component selection and theming; load it before writing UI code.
